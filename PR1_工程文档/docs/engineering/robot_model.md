## 2. 为什么是自行建模：原版 URDF 找到了，但不是这个底盘

按“先找现成模型”的要求，在本机找到了上一代整机 URDF 并已留档：
`assets/reference/robot_a_description/`（来源：微信文件缓存 2026-07 包；
原始路径 `<your-ws>/robot_ws/robot_a_description/urdf/robot_a.urdf`，已不存在，
依据 VSCode 本地历史的 `entries.json` 确认）。

实测对照（左列由 STL 包围盒与 URDF 关节原点直接量出）：

| 项目 | 参考 URDF（上一代整机） | PDF（AGL-CHS-03-F01 V1.2） | 是否一致 |
|---|---|---|---|
| 轮径 | `wheel_fl_link.STL` = 152.4 × 151.9 × 60.0 mm；关节 z=0.0762 → **6 寸轮** | **8 寸全向轮 210 mm** | ✗ |
| 底盘水平尺寸 | `base_link.STL` 700 × 600 mm | **726 × 726 mm** | ✗ |
| 高度 | 结构含升降/双臂/头部，总高 1270 mm | 底盘本体 **251 mm** | ✗ |
| 质量 | base_link 122.48 kg（整机含上半身） | 底盘自重 **≤65 kg** | ✗ |
| 驱动 | 4 × 6 寸（关节名带麦轮语义） | 4 × 8 寸**全向轮**，驱动集成于电机 | ✗ |
| 雷达 | `radar_fr/rl` 两个 3D 雷达，位置在模型里 | 2 × 3D 固态雷达对角布置 | ≈（数量一致，位姿未核对） |

结论：参考模型是**上一代整机**，直接拿来当 E05 交付会与规格书不符（轮径差 38%、
包络差 3.7%、质量差近一倍），因此按 PDF 自行建立最小模型，
同时**复用它的坐标约定**（`base_footprint` 在地面、`base_link` 在轮轴平面、
轮关节名 `base_wheel_*_joint`），以便与既有 `robot_a_sim_control` 控制桥对接。

## 3. 模型内容（按三视图）

### 3.1 三视图读出的形状（2026-10-31 读图结果）

**俯视图**：车体是「**旋转 45° 的方形 + 四角截平**」的八边形：

- 4 个 45° 斜面（NE / NW / SE / SW 朝向）—— 每个斜面上**平行安装一个全向轮**（轮面沿斜面，
  轮轴 = 斜面法向，水平 45°），轮与车体之间有明显支架；
- 4 个被截平的轴向面（前 / 后 / 左 / 右）；
- 顶部中央为人形上装接口板 **254 × 190 mm**；
- 两台 3D 固态雷达**对角**布置，带支座立起（等轴测图里两台都在顶面对角）。

**前视图**：离地总高 **H = 251**，车体本身高 **226**（251 − 25 离地），轮子只在车体下方外露；
右侧另有一个 **75** 的竖向尺寸（车轮相对车体底面的外露量，与 105 − 25 = 80 mm 的计算接近，
差异属图纸取值，记录但不强行对齐）。

### 3.2 尺寸语义（重要：规格书与图纸的口径不同）

图纸上 **726** 这条尺寸线是**与轮子外缘相切的 45° 细线**，因此它量的是
「**跨两对轮、垂直于 45° 斜面**的距离」，**不是 X/Y 外接方盒**：

```text
e + W/2 = 726 / 2 = 363 mm      e = 轮心到中心的法向距离，W = 轮宽
取 W = 60 mm（假设）            ⇒ e = 333 mm
轮心 |x| = |y| = e/√2           ⇒ 235.46 mm
X/Y 外接包络 = (e + D/2 + W/2)·√2 = 661.8 mm
```

所以：**车体 643 × 656，跨轮 726，X/Y 外接包络 662**。规格书表格里写「整机尺寸 726×726×251」，
若按外接方盒理解会差 64 mm —— 这个冲突已登记在第 5.2 节，**建模按图纸语义**，
Nav2 footprint 建议用实际占据的 662 八边形（E11 定稿）。

### 3.3 模型树

```text
base_footprint                       地面投影（URDF 根，导航/里程计平面原点）
└─ base_link                         z = 0.105 m（= 轮半径，轮轴平面）
   ├─ wheel_{fl,fr,rl,rr}_link       连续关节，轮心 (±0.2355, ±0.2355)，轮轴水平 45°
   ├─ mount_plate_link               顶部中央安装板坐标帧（254 × 190，仅坐标，无几何）
   ├─ lidar_front_link (fixed)       对角 (+0.13, +0.13)，z = 0.251 + 支座 + 半高
   │  └─ imu_link      (fixed)       IMU 集成于主雷达内（PDF 2.5）
   └─ lidar_rear_link  (fixed)       对角 (−0.13, −0.13)
```

几何实现：

- **车体**：由 `tools/engineering/gen_chassis_mesh.py` 生成的八边形棱柱 STL（32 个三角形），
  visual 与 collision 都用它。棱柱是**凸体**，Isaac Sim 用凸包做碰撞与真实形状完全一致；
- **轮子**：圆柱（D = 210 mm、宽 60 mm），关节坐标系用 `rpy=(90°, 0, φ+90°)` 把 z 轴转到轮轴方向，
  因此圆柱几何、惯量、(0,0,1) 关节轴三者天然一致；
- 惯量：车体按等包络长方体解析计算，轮按实心圆柱解析计算（改参数自动重算）；
- 雷达与 IMU 不建碰撞体（避免与自身或上方载荷互顶）。

## 7. 怎么用（自己复现）

```bash
cd ${NAV_WS}

# 1) 展开 xacro 并做结构校验（不需要仿真）
source /opt/ros/humble/setup.bash
xacro src/robot_description/urdf/agl_chs_03_f01.urdf.xacro > /tmp/chassis.urdf
check_urdf /tmp/chassis.urdf

# 2) 在 Isaac Sim 里导入 + 稳定性+落体+USD 回读全套检查（headless，约 1 分钟）
./tools/engineering/e01_run_sim_startup.sh results/w2/e05 tools/engineering/e05_import_check.py results/w2/e05
sed -n '/== 静置结果/,$p' results/w2/e05/import_check.txt

# 3) GUI 里目视（E05 剩余项 4）
${ISAAC_SIM_ROOT}/isaac-sim.sh   # 先 source /opt/ros/humble
#   File > Open: assets/robot_a_chassis_agl_chs03_f01.usd
#   或 Extensions > Isaac Sim URDF Importer 选择 urdf 目录下的 xacro 展开结果
```

> ⚠️ **导入时必须解决 `package://` 路径**：Isaac Sim 的 URDF 导入器不会解析
> `package://robot_description/meshes/...`（除非导入进程 source 了工作空间的 `install/setup.bash`）。
> 解析失败时它**只打一条 Warning 就跳过整个网格**，表现是**车体消失、只剩轮子和悬空的雷达**。
> 本仓库的处理：`tools/engineering/e05_import_check.py` 展开 xacro 时用
> `mesh_dir:=file://<绝对路径>/src/robot_description/meshes` 覆盖；验收脚本里有
> “车体网格已加载 + 网格尺寸 643×656×226” 这条回归检查，防止再漏。

修改参数（例如拿到真实轮心位置后）只需改 xacro 的 `<xacro:arg>`，
惯量与轮速上限会自动跟着重算：

```bash
xacro src/robot_description/urdf/agl_chs_03_f01.urdf.xacro wheel_offset_x:=0.35 wheel_offset_y:=0.31
```
