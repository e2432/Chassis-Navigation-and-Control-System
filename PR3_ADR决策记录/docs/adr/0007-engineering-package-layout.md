# ADR-0007：工作空间的包划分（七包 + 一个既有包）

- 状态：**提议（待算法成员签认）**
- 日期：2026-10-30
- 决策者：工程侧（成员三）提出；协作方：算法侧（成员四）
- 相关任务：E03、E04

## 背景

路线书 E03 给出建议的七包划分，并明确要求“与算法成员确认后采用，**不重复建立已有同职责包**”。
现实中已存在 2026-10-23 打包的 `robot_a_sim_control`，它同时承担了仿真控制桥、轮速里程计、
真值定位、Nav2 配置与巡航状态机——刚好横跨建议划分里的 `robot_sim`、`robot_navigation`、
`robot_bringup` 三个包。

## 决策

1. 建立路线书建议的七个包（`robot_description`、`robot_sim`、`robot_bringup`、
   `robot_navigation`、`robot_benchmark`、`robot_safety`、`robot_mpc`）；
2. 把 `robot_a_sim_control` **原样纳入**仓库，不重写、不修改源码，并在
   `docs/engineering/package_roles.md` 第 3 节登记逐项迁移计划；
3. 迁移完成前，`robot_a_sim_control` 仍是唯一可运行链路；新包以“骨架 + 明确未实现”
   的形式存在，**不得**假装已提供同能力；
4. 每个能力同一时间只能有一处生效，迁移提交必须同时更新职责表与接口契约。

## 备选方案与不采用的理由

| 方案 | 不采用的理由 |
|---|---|
| 只在既有包上加功能 | 会继续把仿真适配、导航参数、安全出口混在一个包里，无法按 E13/E17 分层，也无法给 MPC 一个干净落点 |
| 直接删掉既有包、从零重写 | 现有链路已能跑通（含 0.5 s 指令超时、真值 TF、Nav2 配置），重写会丢掉已验证的行为，并占用 W2 的时间 |
| 把既有包拆成三个包一次迁完 | 拆分需要先有 E09（唯一 TF 树）与 E11（地图对齐）的验证证据，否则拆完无法判断功能是否退化 |

## 后果

- 正面：构建一次覆盖全部包，算法成员可从第一天起在同一工作空间里工作；
  `robot_benchmark` 的契约可以先于实现建立（E04 得以完成）。
- 负面：短期内仓库里同时存在“新骨架”和“旧实现”，容易误用。
  缓解：每个新包 README 顶部写明“状态：骨架/未实现”，验收脚本检查未实现接口必须显式失败。
- 遗留：迁移期间需要双份记录（职责表 + 接口契约变更记录），属可接受成本。

## 需要确认的问题

- [ ] 七包划分本身是否同意（尤其 `robot_safety` 与 `robot_navigation` 的边界）；
- [ ] 是否接受“既有包只迁移、不重写”的做法；
- [ ] 迁移触发条件（表中判定条件）是否合适。
