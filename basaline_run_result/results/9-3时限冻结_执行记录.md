## 4. 需要算法侧审的点（9-3 分工：工程组执行、算法组审核阈值与公平性）

1. **阈值合理性**：`T_s` 是否过松/过紧。过松会让超时类失败无法暴露，过紧会把合理慢行判成失败。请对照 §1 的 `1.5×max_j` 与实际中位数判断。
2. **公平性**：`T_s` 对四个控制器完全相同；本工作集只跑了 DWA/MPPI/TEB（按 2026-11-14 决定，MPC 不参与 9-3），但 MPC 后续接入时**沿用同一 T_s**，不得为 MPC 单独调时限。
3. **数据口径**：只统计成功 run；失败 run 已如实保留在 `run.json` 里（`metrics.success=false` + `failure_class`），可复核。
4. 若你们认为某个场景的中位数样本量（5 个种子）不足，工程侧可以扩到 20 种子再冻结——但那会把正式采集提前跑掉，需要你们明确要求。
