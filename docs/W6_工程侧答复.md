## 2. `/mpc/obstacles` 数据源口径（待确认）

按契约与 `msg/README.md` 冻结语义：

| 项 | 口径 |
|---|---|
| 类型/话题 | `mpc_controller/ObstacleStateArray`，`/mpc/obstacles` |
| QoS/频率 | reliable、depth 10；目标 **10~20 Hz**，与插件 20 Hz 控制拍匹配 |
| 坐标系 | `header.frame_id = odom`；`position`/`velocity` 均为 odom 帧 |
| 时间戳 | `header.stamp` = 最新估计时刻；单个障碍 `stamp` = 该障碍估计时刻；统一仿真时钟 |
| id | 跨帧稳定；`radius` 单圆近似（m）；不加协方差 |
| 空数组 | 时间戳有效的空数组 = 清空动态障碍；**不代表感知正常** |
| 单障碍过期 | 单障碍 `stamp` 超 `obstacle_timeout=0.5 s` → 丢弃该障碍，心跳仍有效 |
| 失联 | header 过期或连续 0.5 s 无消息 → 跟踪器失效 → 告警 + 零速；**不得持续发有效空数组** |

- 插件侧已实现：按 `now - stamp` 用 `velocity` 把障碍位置外推到当前时刻，再送入 MPC。
- **发布方归属待确认**：正式导航应由感知/跟踪器节点发布（工程侧？M3 跟踪器？）。
- 在真实跟踪器就绪前，建议增加一个**仅用于 W6 集成测试**的场景障碍发布器：
  只读 `docs/scenarios/instances.yaml`，按契约轨迹发布行人/静态障碍，10~20 Hz；
  该发布器**不用于正式成绩**，正式导航禁止用它与 mock 心跳。

## 3. `qp_timing` / `ablation` / `solver_fail` 落盘口径（待确认）

### 3.1 `qp_timing`

沿用契约 v1 字段，不新增键：

```json
"qp_timing": {"solves": 240, "mean_ms": 9.8, "p95_ms": 12.4, "max_ms": 18.0}
```

- `solves`（K）：该 run 中调用 `MpcCore::solve` 的控制拍数（每拍一次外环，含 `n_sqp`
  次 OSQP；失败也计数）。
- `mean_ms` / `p95_ms` / `max_ms`：上述每次外环调用的墙钟耗时统计；`p95` 取样本 95 分位。
- 原始数组 `qp_ms` 仍按契约写入 `trajectory.npz`（长度 K）。
- **采集方式（已实现，待契约确认）**：新增 `mpc_controller/MpcDiagnostics`，逐拍发布
  `/mpc/diagnostics`，字段：`header`、`success`、`fallback`、`alarm`、`solve_ms`、
  `qp_iterations`、`fallback_streak`、`max_slack`、`obstacle_count`、
  `static_field_used`、`status`。
- 采集器聚合：`solves` = 收到的逐拍诊断数；`mean_ms`/`p95_ms`/`max_ms` 用 `solve_ms`；
  原始 `qp_ms` 写 `trajectory.npz`。该消息/话题需契约变更 PR 双方确认。

### 3.2 `ablation`

契约要求的 6 个键，`controller=mpc_cpp` 时填：

```json
{"vo": false, "esdf": false, "slack": true, "terminal": true, "N": 40, "q_ratio": 0.1}
```

- `vo=false`：C++ 核心不做速度障碍过滤（直接使用障碍状态约束）。
- `esdf=false`：使用圆/墙解析 clearance，不建 EDT/ESDF。
- `slack` / `terminal` / `N` / `q_ratio`：取插件实际参数（`q_ratio = q_long/q_lat`）。
- 若后续 C++ 实现 VO/ESDF，再按实际值更新；不得为了对齐 W4 原型填写 `true`。

### 3.3 `solver_fail`

- 插件已实现：求解失败 → 本拍零速；连续失败 `fallback_streak ≥ 5`（20 Hz 下 0.25 s）
  → 置 alarm。
- 建议判定：一个 run 中**任意控制拍触发 alarm**，且该 run 最终失败且不属于
  `collision` / `timeout`，则 `failure_class = "solver_fail"`。
- 失败分类优先级建议：`collision` > `timeout` > `solver_fail` > `other`。
- 建议在 `params`（自由字典）记录 `qp_fallback_streak_max`、`qp_alarm_count`、
  `qp_solve_count`，不新增 run.json 顶层字段。
