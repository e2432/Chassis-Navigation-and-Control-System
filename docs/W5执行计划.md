## 0. 一句话

W5 算法线按关键路径排序：**先排 M2 基线阻塞 → C++ 插件骨架 + controller_server 加载 smoke → OSQP C++ smoke → M5 先验地图定位 spike（双条件闸门通过后启动）→ W6 前置**。W5 不追求完整导航成功；EDT 与完整 MPC 移植留 W6。

关键路径（不可破）：Python MPC 数学验证（W4 已完成）→ C++ QP 与 Nav2 插件（W5~W6）→ Isaac Sim 真实闭环（W6）→ 五场景 × 三基线公平比较（W6~W7）→ M4 可复现避障实验报告（W8）。

W4 遗留（并入 D1~D2）：#9 基线三项——基线调参方案 / 入库时序 / 时限回填，以及基线补比终判。

| 9 | TF 口径 | 实际 TF 树为 `map → odom → base_footprint → base_link`，`base_footprint_joint` 已存在；Nav2 统一 `robot_base_frame: base_footprint`、局部 costmap `global_frame: odom`，不需要补 TF；关键是参数与工程 launch 不各用一套 base 帧。 |
| 10 | M5 场景/路线/地图 | `narrow_passage_01` + 固定 30 s 往返路线（约 0.3 m/s）；建图与定位使用同一场景与同一 `world_pose`，路线不得超出地图覆盖；地图存 `nav_ws_core/maps/narrow_passage_01/map.pcd`。若走廊几何重复导致 ICP 退化，切换 `dead_end_01` U 形场景。 |
| 11 | M5 定位判据 | 30 s 从初始化成功后计时；与独立 GT 同坐标系比较：位置 RMSE ≤0.2 m、末误差 ≤0.3 m、最大误差 ≤0.5 m、航向 RMSE ≤2°；输出 ≥10 Hz、无 >0.5 s 断流；相邻跳变扣除正常运动影响；已知初始位姿 + ICP，目标 5 s 内完成初始化且误差 ≤0.3 m。阈值先作试运行目标，首跑后只校准阈值、不改指标定义。 |
| 12 | M5 实施顺序 | 明确支持 ROS2/Humble 的 FAST_LIO_LOCALIZATION 移植版（1 天 spike，pin commit；原始 `iral-ntua/FAST_LIO_LOCALIZATION` 为 ROS1 catkin，不作 Humble 候选）→ 失败切 PCL ICP/NDT 自研最小定位节点 → 走廊 ICP 退化切 `dead_end_01` → 仍失败则降级为「建图 + 连续 LIO 30 s」，明确不算先验地图定位成功，不阻塞 M3/M4；严格限制 spike 工时，不挤占 M3/M4。 |
| 13 | M5 放置 | FAST-LIO2 接入、适配、launch、定位节点放 `nav_ws_core/src/slam_bridge`（算法线）；地图放 `nav_ws_core/maps/`。 |
| 14 | 基线协助 | W5 前 1~2 天集中排除：搭档负责基线运行、日志、入库；你负责参数方案、异常分析、成绩判读，不全面接管。W5 必须保留 OSQP C++ smoke 与 Nav2 插件加载验收。 |
