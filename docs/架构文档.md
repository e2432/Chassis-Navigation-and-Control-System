# 架构文档

> M0 交付物（W1）。配套文档：docs/接口契约.md（互审主对象）、docs/指标定义.md。术语见 GLOSSARY.md，路线决策见 docs/adr/。

## 系统拓扑

基准模式下的组件与数据流：

```
Isaac Sim（物理仿真 + 真值几何 + 真值定位）
   │  ros2_bridge
   ├── /lidar/points ──→ costmap_2d（VoxelLayer）──→ controller_server（自研局部控制器）
   ├── /imu ──────────→ Nav2 / FAST-LIO2
   ├── /odom（真值）──→ Nav2
   └── 真值接口 ──────→ 基准评测（碰撞 / 间距判定，见 docs/指标定义.md）

Nav2：planner_server（NavFn 全局规划）+ controller_server（自研局部控制器插件）──→ /cmd_vel
底盘抽象层：/cmd_vel → 底盘驱动（仿真或真机）
安全急停层：订阅 /lidar/points，外缘距离 < 0.15 m 强制停止（可恢复）；急停计数 → 指标采集
基准编排（Python）：场景重置 / 障碍随机化 / 目标注入 → benchmark.run(scenario) → 指标 dict
RViz：可视化
```

## 运行模式

| 模式 | 定位链 | 地图来源 | 用途 |
|---|---|---|---|
| 基准模式 | 真值定位顶替 `map→odom`，`/odom` 为仿真真值 | 场景几何离线生成 | M2~M4 评测；避障算法验证与 SLAM 管线解耦 |
| SLAM 模式 | FAST-LIO2 提供定位 | SLAM 建图 | M5 建图验证；不参与基准评测 |

降级预案：Isaac Sim 不通时改用 Gazebo + GPU 射线 3D 雷达近似 Mid-360，保留 3D 点云管线与 VoxelLayer 路径（ADR-0002 只降保真度，不退 2D）。

## tf 树

遵循 REP-105：`map → odom → base_link → lidar_link`。基准模式下 `map→odom` 由真值定位提供。

## 节点与职责

| 节点 / 组件 | 职责 | 责任线 |
|---|---|---|
| Isaac Sim + ros2_bridge | 物理仿真、传感器仿真、真值输出 | 工程线 |
| 底盘 / 传感器模型（URDF） | 全向底盘 + Mid-360 模型、真值 `/odom` | 工程线 |
| planner_server | NavFn 全局规划（Nav2 现成） | 现成 |
| controller_server | 自研局部控制器插件（MPC，ADR-0001） | 算法线 |

| 安全急停层 | 独立急停保护 + 急停计数 | 工程线 |
| 基准编排（Python 包 `benchmark`） | 场景编排、指标采集、`benchmark.run()` | 工程线（指标定义归算法线） |

## 与可迁移性的关系

可迁移性（GLOSSARY）两条验收属性的架构落点：

- **Sim2Real**：导航管线只消费标准话题（`/cmd_vel`、`/odom`、`/lidar/points`、`/imu`、`/tf`）；真值定位仅存在于基准评测侧，不进入导航算法。换真机时只替换传感器驱动与参数配置，算法零改动。
- **平台无关**：算法统一输出 `/cmd_vel`，底盘差异收敛至参数化底盘描述文件（schema 见 docs/接口契约.md）与薄底盘驱动节点。
