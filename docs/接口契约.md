## 通用约定

- **命名**：ROS 2 标准话题名优先（`/cmd_vel`、`/odom`、`/imu`、`/tf`）；自定义话题 `/<模块>/<动词>`（如 `/mpc/predicted_path`）。
- **帧**：REP-105，`map → odom → base_footprint → base_link → {lidar_front_link → imu_link, lidar_rear_link}`（实测 TF 树，v1.1 修订）。`base_footprint` 是 URDF 根（地面投影），`base_link` 在轮轴平面（z=+0.105 m）；`tf2_echo odom base_link` 照样成立。`lidar_link` 只存在于上一代资产，新契约不再使用。
- **单位**：全 SI（m、rad、m/s、rad/s）；时间戳用仿真时钟。
- **消息类型**：ROS 2 Humble 标准类型。`/cmd_vel` 用 `geometry_msgs/Twist`（Humble Nav2 行为）；全向底盘 `vy` 走 `linear.y`。

## 话题契约

| 话题 | 类型 | 频率 | QoS | 生产者 | 消费者 |
|---|---|---|---|---|---|
| `/cmd_vel` | `geometry_msgs/Twist` | 20 Hz | reliable, depth 1 | controller_server | 底盘抽象层 |
| `/odom` | `nav_msgs/Odometry` | ≥50 Hz（实测 60.00 Hz） | reliable | 仿真（真值输出） | Nav2 |
| `/lidar/points` | `sensor_msgs/PointCloud2` | 10 Hz | best_effort | 仿真雷达（E08 自建射线投射，双台对角，当前仅前向发流） | VoxelLayer、安全急停层 |
| `/imu` | `sensor_msgs/Imu` | 标称 200 Hz；仿真发布 ≈60 Hz（实测 60.11 Hz） | best_effort | 仿真 | Nav2、FAST-LIO2 |
| `/tf`、`/tf_static` | `tf2_msgs/TFMessage` | — | 标准 tf2 | 各节点 | 全体 |

注（v1.1 实测口径）：
- **点云话题统一为 `/lidar/points`**。工程侧现发 `/points_raw`，由工程侧改脚本 + RViz + 文档（3 处）收敛到本名；契约名字不变。
- **IMU 频率**：IMU 数据在物理步内更新（仿真 60 Hz），发布绑在物理步上，200 Hz 达不到——**标称 200 Hz / 仿真发布 ≈60 Hz**。高频动态下采样不足，IMU 相关指标不得按 200 Hz 设计。
- **`/odom` 语义**：`header.frame_id=odom`、`child_frame_id=base_footprint`、twist 表达在**机体系**；真值模式零漂移。场景重置时真值位姿跳变、twist 置 0。
- **QoS 已定**：点云 / IMU 为 best_effort（工程侧从 reliable 切换后复测）；`/odom`、`/cmd_vel` 保持 reliable。

注：主感知话题是 3D 点云（ADR-0002），`sensor_msgs/LaserScan` 的 `/scan` 不进 v1；如调试需要 2D 投影，命名 `/debug/scan`，不作为契约接口。

## 障碍状态消息（schema v1）

「障碍跟踪」（GLOSSARY）节点订阅 `/lidar/points` + `/odom`，输出障碍状态列表，作为自研局部控制器的避障输入。位置 / 速度记 `odom` 帧；`radius` 为单圆近似，复杂外形以 polygon 扩展时升版本。消息定义住 `mpc_controller` 包，不新增包。

```
# mpc_controller/msg/ObstacleState.msg
uint32 id                          # 帧间关联 id
geometry_msgs/Point position       # m，odom 帧
geometry_msgs/Vector3 velocity     # m/s，odom 帧
float32 radius                     # m，单圆近似
builtin_interfaces/Time stamp
---
# mpc_controller/msg/ObstacleStateArray.msg
std_msgs/Header header
ObstacleState[] obstacles
```

通路约定：开发期（W2/W4 Python 原型）可以场景脚本合成状态作输入；基准打分通路必须使用障碍跟踪输出（或降级仅静态），仿真真值仅限 `/debug` 形态、不进算法通路。

## 底盘参数化描述（schema v1.1）

每种底盘一份 `chassis.yaml`，由算法侧与驱动共同消费。限速**分两层**（v1.1 修订）：
**底盘能力**取规格书实测/标称值，**基准任务限速**写进 `velocity_smoother`，基准实验按任务限速比较。

```yaml
chassis:
  type: omni                  # omni | mecanum | diff
  footprint:                  # v1.1：填实际多边形（AGL-CHS-03-F01 八边形，实测）
    polygon: [[0.3215, 0.0886], [0.0821, 0.328], [-0.0821, 0.328], [-0.3215, 0.0886],
              [-0.3215, -0.0886], [-0.0821, -0.328], [0.0821, -0.328], [0.3215, -0.0886]]
    # 八边形 = 旋转 45° 方形 + 四角截平：half_x 0.3215 / half_y 0.328（车体 643×656），
    # 45° 斜面法向距离 face_dist 0.290；顶点由 |x|+|y|=0.290√2 与 x=±0.3215、y=±0.328 求交。
    # 整机外接 726 mm 是跨轮距离（含轮），不含轮车体包络 662 mm。
  limits:
    capability:               # 底盘能力（规格书：0–2 m/s）
      v_max: 2.0              # m/s
      v_min: -2.0
      vy_max: 2.0
      omega_max: null         # 规格书未给，待整机成员补
      acc_max: null           # 规格书未给，待整机成员补
      alpha_max: null
    task:                     # 基准任务限速（velocity_smoother 使用）
      v_max: 1.0              # m/s
      v_min: -1.0
      vy_max: 1.0
      omega_max: 1.5          # rad/s
      acc_max: 1.0            # m/s²（v1.0 遗留值，待 capability 补齐后复核）
      alpha_max: 2.0          # rad/s²（同上）
  wheels:                     # 4×45° 全向轮（实测）
    radius: 0.105             # m，轮径 φ210 mm
    center: {x: 0.23546, y: 0.23546}   # 轮心到中心，四角对称（跨轮 0.726 反解）
    mount_angle_deg: 45       # 轮轴方位角（斜面法向）
    ik: omni_45               # 逆解形式：4×45° 全向轮
  sensors:                    # 安装位姿（相对 base_link，实测/URDF）
    lidar_front: {xyz: [0.13, 0.13, 0.2185], rpy: [0.0, 0.0, 0.0]}
    lidar_rear:  {xyz: [-0.13, -0.13, 0.2185], rpy: [0.0, 0.0, 0.0]}
    imu: {parent: lidar_front, xyz: [0.0, 0.0, 0.0]}   # IMU 集成于主雷达内（PDF 2.5）
```

## 基准套件 API

Python 包 `benchmark`（工程线 W4 实装，schema 由本契约锁定）：

```python
benchmark.run(scenario: str) -> dict
```

**scenario 键**（v1 固定 5 个）：`static_avoid` | `dynamic_pedestrian` | `narrow_passage` | `dead_end` | `mixed`

**返回 dict**（场景级，每场景 20 次聚合；指标定义见 docs/指标定义.md）：

```python
{
  "scenario": "static_avoid",
  "runs": 20,
  "success_rate": 0.95,      # 成功数 / 20
  "time_to_goal_s": 12.3,    # 中位数，仅成功 run
  "path_length_m": 15.2,     # 中位数，仅成功 run
  "smoothness": 0.42,        # 中位数，无量纲（归一化控制量总变差）
  "min_clearance_m": 0.41,   # 20 次中位数（每次先取 run 内最小）
  "estop_count": 1,          # 20 次合计
}
```

指标 7「动态应变」是套件级字段（动态场景合并成功率），不进单场景 dict：

```python
dynamic_stress = (dynamic_pedestrian 与 mixed 成功数之和) / (两场景总 runs)
```

由套件汇总（`benchmark.run_suite()` 或分析脚本）产出。

注（v1.1 对齐）：指标/场景键**以本契约为准**。工程侧 `robot_benchmark` 现有键（`time_to_goal` / `path_length` / `min_clearance`）将对齐为上表带单位后缀的键名，并补 `dynamic_stress` 套件级聚合与 5 个 scenario 键。

## 场景实例表（schema v1.1）

场景实例（GLOSSARY）以**逐种子实例化表**定格，是 Python 原型与 Isaac 基准套件的同源载体：**两侧直接加载同一份表，不再各自抽样**。

- **路径**：`nav_ws_core/scenarios/instances/<scenario>_instances.yaml`（5 分文件、每场景 20 实例），**由工程侧生成**（生成器随基准套件入库、可复算）；算法侧只读消费。v1.2 写的 `docs/scenarios/instances.yaml` 单表路径作废。
- **规模**：100 实例 = 5 场景 × 20 run；种子 = 场景键序（`static_avoid`=1 … `mixed`=5）× 100 + run 序（1~20）。
- **坐标约定**：path frame——起点 (0, 0)、名义行进方向 +x；套件可在世界系整体刚体挪移。目标航向 = 起点→目标连线方向（GLOSSARY「目标位姿」）。
- **抽样实现由工程侧定格**（生成器入库、可复算）；**表内数值即最终事实**，重建只认表、不认抽样。表即场景事实：两侧直接加载、不得改动表内几何。
- **字段命名收编交付实况**（v1.3）：字段名以工程侧已入库表为准，v1.2 示例字段名作废，映射见下表。

**字段**（示例值取 `static_avoid_01` / `narrow_passage_01` / 交付行人实际值）：

```yaml
instances:
  - scenario_id: static_avoid_01   # 实例 id：<scenario>_<run 序两位>
    scenario: static_avoid         # 5 个 scenario 键之一
    scenario_index: 1              # 场景键序 1~5（种子公式中的场景序；v1.3 补录）
    run_index: 1                   # run 序 1~20
    seed: 101                      # = scenario_index × 100 + run_index
    path_length_m: 10.081          # 起终点直线长度（v1.3 补录）；static_avoid/dynamic_pedestrian
                                   # 为 9.5~10.5 抽样（v1.3 追认）、mixed 11~13，余为布局定值
    asset_version: '2026-11-03'
    map_version: e05_min_scene@2026-11-01
    robot_start: {x: 0.0, y: 0.0, yaw: 0.0}
    goal: {x: 10.081, y: 0.0, yaw: 0.0}
    obstacles:                     # 静态障碍（0~n 个），type 判别
      - {type: circle, x: 5.278, y: -0.422, r: 0.573}   # 圆障碍
      - {type: box, x: 7.449, y: 0.83, w: 2.899, h: 0.2}  # 轴对齐矩形（墙体类，窄通道/死角用）
    dynamic:                       # 动态行人（0~2 个），轨迹语义见下
      - {type: pedestrian, radius: 0.3, start: {x: 5.903, y: -3.0},
         velocity: {vx: 0.0, vy: 0.768}, start_time_s: 4.892, stop_at_y: 3.0}
    timeout_s: 60                  # 场景时限初值（W4 基线入库后按校准公式回填）
    goal_tolerance: {pos_m: 0.25, yaw_rad: 0.25}
    solvable: true                 # 连通性校验通过与否（校验详情见 validity）
    recovery_required: false       # 是否需要倒车恢复（dead_end 类实例置 true）
    passage: null                  # narrow_passage 时：{net_width_m, length_m, margin_per_side_m, min_required_margin_m}
    dead_end: null                 # dead_end 时：{mouth_width_m, depth_m}
    validity: {connectivity_checked: true, robot_radius_m: 0.35, grid_m: 0.1, resamples: 0}
```

**v1.2 → v1.3 字段映射**（v1.2 字段名作废）：

| v1.2 字段 | v1.3 字段 | 说明 |
|---|---|---|
| `run` | `run_index` | 改名 |
| `time_limit_s` | `timeout_s` | 改名 |
| `pedestrians: [{x_cross, speed, t_meet, dir, r}]` | `dynamic: [{type: pedestrian, radius, start, velocity, start_time_s, stop_at_y}]` | 结构收编交付，语义见下 |
| `walls: [{x0, y0, x1, y1}]` | `obstacles: [{type: box, x, y, w, h}]` + `passage` / `dead_end` 结构化字段 | 墙体收编交付表达 |
| `obstacles: [{x, y, r}]` | `obstacles: [{type: circle, x, y, r}]` | 加 `type` 判别 |
| （无） | `scenario_id`、`asset_version`、`map_version`、`robot_start`、`goal_tolerance`、`solvable`、`recovery_required`、`validity` | 交付增值字段收编 |
| `docs/scenarios/instances.yaml` | `nav_ws_core/scenarios/instances/<scenario>_instances.yaml` | 5 分文件定格 |

注：`scenario_index`、`path_length_m` 为 v1.3 补录字段（交付表暂未含，由工程侧导出补写；`path_length_m` = 起终点直线长度，path frame 下与 `goal.x` 一致）。

**行人轨迹语义**（v1.3 分段口径，收编交付 `start_time_s` / `stop_at_y`）：行人自 `start` 出发沿 y 向匀速直线横穿、行至 `stop_at_y` 停住：

- `t < start_time_s`：停在 `start`（未启动）；
- `start_time_s ≤ t < t_arrive`：`x = start.x`、`y = start.y + vy · (t − start_time_s)`（匀速直线、不折返）；
- `t ≥ t_arrive`：停在 `stop_at_y`；`t_arrive = start_time_s + |stop_at_y − start.y| / |vy|`。

方向约定：**`vy` 由 `start` 指向 `stop_at_y`**（P0-1 符号修复后口径；修复前冻结表存在符号反向，一切消费以修复后为准）。
派生量（与 5场景需求清单抽样口径对应）：`dir = sign(vy)`（+1 向 +y、−1 向 −y）；`t_meet = start_time_s + |start.y| / |vy|`（行人行至行进线 y=0 的时刻，对应「相遇时刻 ±2 s」）。

## 评测记录 schema（v1）

逐 run 原始数据落盘口径，**Python 原型与 C++ 插件同口径**（M-paper 三钩子之一的载体；基线 run 记录亦同 schema）。每次 run 在**生产者各自的输出根**（原型 `prototype/mpc_numpy/out/`、套件自带）下产出 `runs/<scenario>/<seed>/` 目录：

**`run.json`**：

```json
{
  "schema_version": 1,
  "controller": "mpc_proto",
  "scenario": "static_avoid",
  "seed": 101,
  "run": 1,
  "ablation": {"vo": true, "esdf": true, "slack": true, "terminal": true, "N": 40, "q_ratio": 0.1},
  "metrics": {
    "success": true,
    "time_to_goal_s": 12.3,
    "path_length_m": 15.2,
    "smoothness": 0.42,
    "min_clearance_m": 0.41,
    "estop_count": 1
  },
  "qp_timing": {"solves": 240, "mean_ms": 3.2, "p95_ms": 6.1, "max_ms": 12.4},
  "failure_class": null,
  "params": {}
}
```

- `controller`：`mpc_proto` | `mpc_cpp` | `dwa` | `teb` | `mppi`。
- `scenario`：基准 5 键之一；离线原型的模拟场景（GLOSSARY）写 `S1|S2|S3`、`seed`/`run` 置 null、目录 `runs/<scenario>/dev/`。
- `ablation`：消融开关快照，**必填**；`q_ratio` = q_long / q_lat。`vo` / `esdf` / `slack` / `terminal` 独立布尔可关，原型与 C++ 插件同语义。
- `metrics`：键名与「基准套件 API」逐 run 对应（单 run 为 `success` 布尔；套件级 `dynamic_stress` 不进 run 记录）。
- `qp_timing`：逐次求解耗时汇总（p95 = 求解耗时样本 95 分位）；原始数组在 `trajectory.npz`。计时口径 = 每控制拍求解外环一次（含 SQP 迭代；离线原型 K = 控制拍数）。
- `failure_class`：`null`（成功）| `collision` | `timeout` | `solver_fail` | `dead_end_reverse` | `narrow_oscillation` | `dynamic_stall` | `other`。
- `params`：可选自由字典（权重等调参快照），便于复现。

**`trajectory.npz`**：

| 数组 | 形状 | 含义 |
|---|---|---|
| `t` | (T,) | 仿真时间戳，s |
| `state` | (T, 3) | [x, y, θ]，地图帧（离线原型为 path frame） |
| `control` | (T, 3) | [vx, vy, ω]，机体系控制指令 |
| `qp_ms` | (K,) | 逐次 QP 求解耗时，ms（K = 实际求解次数） |
