## 通用约定

- **命名**：ROS 2 标准话题名优先（`/cmd_vel`、`/odom`、`/imu`、`/tf`）；自定义话题 `/<模块>/<动词>`（如 `/mpc/predicted_path`）。
- **帧**：REP-105，`map → odom → base_footprint → base_link → {lidar_front_link → imu_link, lidar_rear_link}`（实测 TF 树，v1.1 修订）。`base_footprint` 是 URDF 根（地面投影），`base_link` 在轮轴平面（z=+0.105 m）；`tf2_echo odom base_link` 照样成立。`lidar_link` 只存在于上一代资产，新契约不再使用。
- **单位**：全 SI（m、rad、m/s、rad/s）；时间戳用仿真时钟。
- **消息类型**：ROS 2 Humble 标准类型。`/cmd_vel` 用 `geometry_msgs/Twist`（Humble Nav2 行为）；全向底盘 `vy` 走 `linear.y`。

## 话题契约

| 话题 | 类型 | 频率 | QoS | 生产者 | 消费者 |
|---|---|---|---|---|---|
| `/cmd_vel` | `geometry_msgs/Twist` | 20 Hz | reliable, depth 1 | controller_server | 底盘抽象层 |
| `/odom` | `nav_msgs/Odometry` | ≥50 Hz（实测 60.00 Hz） | reliable | 仿真（真值输出） | Nav2 |
| `/lidar/points` | `sensor_msgs/PointCloud2` | 10 Hz | best_effort | 仿真雷达（E08 自建射线投射，双台对角，当前仅前向发流） | VoxelLayer、安全急停层 |
| `/imu` | `sensor_msgs/Imu` | 标称 200 Hz；仿真发布 ≈60 Hz（实测 60.11 Hz） | best_effort | 仿真 | Nav2、FAST-LIO2 |
| `/tf`、`/tf_static` | `tf2_msgs/TFMessage` | — | 标准 tf2 | 各节点 | 全体 |

注（v1.1 实测口径）：
- **点云话题统一为 `/lidar/points`**。工程侧现发 `/points_raw`，由工程侧改脚本 + RViz + 文档（3 处）收敛到本名；契约名字不变。
- **IMU 频率**：IMU 数据在物理步内更新（仿真 60 Hz），发布绑在物理步上，200 Hz 达不到——**标称 200 Hz / 仿真发布 ≈60 Hz**。高频动态下采样不足，IMU 相关指标不得按 200 Hz 设计。
- **`/odom` 语义**：`header.frame_id=odom`、`child_frame_id=base_footprint`、twist 表达在**机体系**；真值模式零漂移。场景重置时真值位姿跳变、twist 置 0。
- **QoS 已定**：点云 / IMU 为 best_effort（工程侧从 reliable 切换后复测）；`/odom`、`/cmd_vel` 保持 reliable。

注：主感知话题是 3D 点云（ADR-0002），`sensor_msgs/LaserScan` 的 `/scan` 不进 v1；如调试需要 2D 投影，命名 `/debug/scan`，不作为契约接口。

## 障碍状态消息（schema v1）

「障碍跟踪」（GLOSSARY）节点订阅 `/lidar/points` + `/odom`，输出障碍状态列表，作为自研局部控制器的避障输入。位置 / 速度记 `odom` 帧；`radius` 为单圆近似，复杂外形以 polygon 扩展时升版本。消息定义住 `mpc_controller` 包，不新增包。

```
# mpc_controller/msg/ObstacleState.msg
uint32 id                          # 帧间关联 id
geometry_msgs/Point position       # m，odom 帧
geometry_msgs/Vector3 velocity     # m/s，odom 帧
float32 radius                     # m，单圆近似
builtin_interfaces/Time stamp
---
# mpc_controller/msg/ObstacleStateArray.msg
std_msgs/Header header
ObstacleState[] obstacles
```

通路约定：开发期（W2/W4 Python 原型）可以场景脚本合成状态作输入；基准打分通路必须使用障碍跟踪输出（或降级仅静态），仿真真值仅限 `/debug` 形态、不进算法通路。

## 底盘参数化描述（schema v1.1）

每种底盘一份 `chassis.yaml`，由算法侧与驱动共同消费。限速**分两层**（v1.1 修订）：
**底盘能力**取规格书实测/标称值，**基准任务限速**写进 `velocity_smoother`，基准实验按任务限速比较。

```yaml
chassis:
  type: omni                  # omni | mecanum | diff
  footprint:                  # v1.1：填实际多边形（AGL-CHS-03-F01 八边形，实测）
    polygon: [[0.3215, 0.0886], [0.0821, 0.328], [-0.0821, 0.328], [-0.3215, 0.0886],
              [-0.3215, -0.0886], [-0.0821, -0.328], [0.0821, -0.328], [0.3215, -0.0886]]
    # 八边形 = 旋转 45° 方形 + 四角截平：half_x 0.3215 / half_y 0.328（车体 643×656），
    # 45° 斜面法向距离 face_dist 0.290；顶点由 |x|+|y|=0.290√2 与 x=±0.3215、y=±0.328 求交。
    # 整机外接 726 mm 是跨轮距离（含轮），不含轮车体包络 662 mm。
  limits:
    capability:               # 底盘能力（规格书：0–2 m/s）
      v_max: 2.0              # m/s
      v_min: -2.0
      vy_max: 2.0
      omega_max: null         # 规格书未给，待整机成员补
      acc_max: null           # 规格书未给，待整机成员补
      alpha_max: null
    task:                     # 基准任务限速（velocity_smoother 使用）
      v_max: 1.0              # m/s
      v_min: -1.0
      vy_max: 1.0
      omega_max: 1.5          # rad/s
      acc_max: 1.0            # m/s²（v1.0 遗留值，待 capability 补齐后复核）
      alpha_max: 2.0          # rad/s²（同上）
  wheels:                     # 4×45° 全向轮（实测）
    radius: 0.105             # m，轮径 φ210 mm
    center: {x: 0.23546, y: 0.23546}   # 轮心到中心，四角对称（跨轮 0.726 反解）
    mount_angle_deg: 45       # 轮轴方位角（斜面法向）
    ik: omni_45               # 逆解形式：4×45° 全向轮
  sensors:                    # 安装位姿（相对 base_link，实测/URDF）
    lidar_front: {xyz: [0.13, 0.13, 0.2185], rpy: [0.0, 0.0, 0.0]}
    lidar_rear:  {xyz: [-0.13, -0.13, 0.2185], rpy: [0.0, 0.0, 0.0]}
    imu: {parent: lidar_front, xyz: [0.0, 0.0, 0.0]}   # IMU 集成于主雷达内（PDF 2.5）
```

## 基准套件 API

Python 包 `benchmark`（工程线 W4 实装，schema 由本契约锁定）：

```python
benchmark.run(scenario: str) -> dict
```

**scenario 键**（v1 固定 5 个）：`static_avoid` | `dynamic_pedestrian` | `narrow_passage` | `dead_end` | `mixed`

**返回 dict**（场景级，每场景 20 次聚合；指标定义见 docs/指标定义.md）：

```python
{
  "scenario": "static_avoid",
  "runs": 20,
  "success_rate": 0.95,      # 成功数 / 20
  "time_to_goal_s": 12.3,    # 中位数，仅成功 run
  "path_length_m": 15.2,     # 中位数，仅成功 run
  "smoothness": 0.42,        # 中位数，无量纲（归一化控制量总变差）
  "min_clearance_m": 0.41,   # 20 次中位数（每次先取 run 内最小）
  "estop_count": 1,          # 20 次合计
}
```

指标 7「动态应变」是套件级字段（动态场景合并成功率），不进单场景 dict：

```python
dynamic_stress = (dynamic_pedestrian 与 mixed 成功数之和) / (两场景总 runs)
```

由套件汇总（`benchmark.run_suite()` 或分析脚本）产出。

注（v1.1 对齐）：指标/场景键**以本契约为准**。工程侧 `robot_benchmark` 现有键（`time_to_goal` / `path_length` / `min_clearance`）将对齐为上表带单位后缀的键名，并补 `dynamic_stress` 套件级聚合与 5 个 scenario 键。
