## 3. 四项拍板（决策记录）

### 3.1 #4 信息公平性口径

| 口径 | MPC 输入 | 三基线输入 | `ablation` 快照 | 用途 |
|---|---|---|---|---|
| **A 栅格口径** | 局部 costmap + 全局路径；`/mpc/obstacles` 只喂**栏杆矩形**（位置 + 半径，速度 0） | 局部 costmap（同一条栏杆带） | `{vo:false, esdf:true, slack:true, terminal:true, N:40, q_ratio:0.1}` | **正式成绩** |
| **B 感知口径** | 局部 voxel `marking=true`（`nav2_common_lidar.yaml`）+ 跟踪器从**同一份** `/lidar/points` 产出行人 | 同一份感知进 costmap（无预测） | `{vo:true, esdf:true, slack:true, terminal:true, N:40, q_ratio:0.1}` | A/B 章节 |
| **C 真值口径** | 直接喂契约解析行人 | 同 | `{vo:true, esdf:true, ...}` | 上限参考，正文标注 oracle |

**口径说明**：

- **A 的 `vo=false`**：栏杆矩形速度恒为 0，速度预测在本口径下未实际生效；如实记录为 `false`，避免读者误认为 A 的成绩包含预测收益。
- **`esdf=true` 的含义**：表示"启用了栅格距离场 / EDT"，**不表示**存在独立 ESDF 话题；与 #2 的"不新增话题"不矛盾。
- **`q_ratio = q_long / q_lat = 0.4 / 4.0 = 0.1`**。
- 旧草案 `docs/W6_工程侧答复.md §3.2` 写 `esdf=false`，与本决策不符；**以本答复为准**，契约 PR 时同步修正，本轮不改旧文件。

### 3.2 #2 静态几何与 EDT

- **结论**：接受"静态几何由算法侧从局部 costmap 算 EDT"；墙体留在 `static_layer`，天然被 EDT 覆盖；**静态圆、墙体都不进 `ObstacleState`**；不新增 ESDF 节点/话题，不扩展消息类型。
- **现状差距**：当前插件用 `/map` 的 chamfer EDT（`distance_field.cpp:36-77`），不是严格的局部 costmap EDT。正式 A 口径改为**局部 costmap 未膨胀栅格**建 EDT；`/map` 场保留为开发/兜底路径，参数建议 `static_field_source: local_costmap|map`（开发默认 `map`，正式 A 用 `local_costmap`）。
- **请工程侧确认（G6）**：未膨胀局部 costmap 的**话题 / 发布频率 / 坐标系**；不能用 inflation 后的 cost 代替几何距离。
- **风险**：A 口径下栏杆矩形与局部 costmap 的 `ped_corridor_layer` band 可能重复计数；A-P0-3 需明确"精确矩形替代 band"或"取 min"，并在验收里检查。

### 3.3 #7 Launch 归属

- **唯一入口**：`ros2 launch robot_bringup nav2_baseline.launch.py baseline:=mpc`；**不新增 `w6_mpc.launch.py`**；不改 `robot_*` 包；`SHARED_CONTROLLER_PARAMS` 仍是 server 级参数唯一来源。
- **mock 心跳**：当前 launch 在 mpc 时无条件 spawn 且 `enabled=True`（`nav2_baseline.launch.py:159-166`）；请改成 launch 参数（如 `mock_obstacles:=false` 默认关闭，或仅 `test_mode:=true` 时启用）。正式 feeder 在场时不得出现第二个 `/mpc/obstacles` 发布者。
- **单栈不变量措辞更正**：校验实际在 `robot_benchmark/nav2_driver.py:378-396`，不是 `runner.py`；事实成立，不要求改代码。

### 3.4 #8 `solver_fail`

- **阈值**：连续 **5 拍**（20 Hz 下 **0.25 s**）OSQP 不收敛 → 记 `alarm`；该 run 最终未成功时写入 `failure_class=solver_fail`。
- **失败优先级**：`collision > timeout > solver_fail > dead_end_reverse / narrow_oscillation / dynamic_stall > other`。
- **仅最终失败生效**：中途 alarm 但最终到达的 run 只进诊断，不改 `failure_class`。
- **`solver_fail_streak_max`**：由算法侧后处理聚合（`max(fallback_streak)` 或最大连续 alarm 拍数），写入 `run.json.params` 或后处理 JSON；**暂不改 `MpcDiagnostics.msg`**，避免额外契约变更。
- **`/mpc/diagnostics`**：接受作为 `/debug` 通道，不作评测必需依赖；是否登记进契约由 PR 决定。
