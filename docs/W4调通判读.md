# W4 离线调通判读（5 基准场景 × 20 实例）

> 2026-11-11。判读口径：`docs/指标定义.md`、`docs/接口契约.md` v1.4、`docs/W4工作手册.md` §1.2/§3；
> 基线缺位，按 2026-11-10 grill 第 6 轮「双段判读」先做四阈值自查，记 **调通（待基线补比）**；
> 终判以 DWA/TEB/MPPI 基线入库后的补比为准。本文不伪造基线数字。

## 0. 结论

- 5 场景 × 20 实例 **100/100 成功**（无碰撞、无超时、无求解失败、无基础设施失败）。
- 四阈值自查 **全部 PASS**：逐场景成功率 100%、最小间距中位数 0.304~0.341 m、急停合计 0、
  `dynamic_stress` 100%（40/40）。
- 结论：**调通（待基线补比）**。正式达标判定留 M3/W6 同环境 `benchmark.run()`。

到达判定 0.25 m / 0.25 rad；碰撞/间距真值裁判含圆障碍、行人与墙体；动态避让由 VO 匀速预测承担；
**一次性规划不重规划、无噪声、无安全急停层**。

**W4 专用 NavFn 参数**：`nav2_w4_params.yaml` 的 `inflation_radius=0.60`（robot 0.30 + d_safe 0.30）、
`cost_scaling_factor=5.0`。W3 的 S1~S3 仍用 `nav2_w3_params.yaml`（0.35 / 3.0），存档基准未动。

## 4. 逐场景 6 指标（20 次聚合）

| 场景 | 成功率 | 到达中位 [s] | 路径中位 [m] | 平滑中位 | 间距中位 [m] | 间距最坏 [m] | 急停合计 |
|---|---|---|---|---|---|---|---|
| static_avoid | 100.0% | 17.90 | 10.652 | 12.495 | 0.337 | 0.314 | 0 |
| dynamic_pedestrian | 100.0% | 16.20 | 9.747 | 4.836 | 0.304 | 0.265 | 0 |
| narrow_passage | 100.0% | 19.65 | 11.776 | 9.107 | 0.331 | 0.302 | 0 |
| dead_end | 100.0% | 20.27 | 12.088 | 14.079 | 0.341 | 0.306 | 0 |
| mixed | 100.0% | 20.77 | 12.389 | 16.189 | 0.304 | 0.292 | 0 |

- 到达时间 / 路径长度 / 平滑度：仅成功 run 的中位数（本数据集全部成功）。
- 最小间距：每个 run 先取 run 内最小，再取 20 次中位数；最坏值为 20 次中的最小值。
- `dynamic_pedestrian` 与 `mixed` 的**动态成绩为乐观上界**（合成障碍状态、无跟踪噪声），
  打分真口径以 M3 基准（跟踪器在线）为准。
- 平滑度 = 归一化控制量总变差（总 TV），不是 TV/拍；W2 存档的 0.025 是 TV/拍，两者不可直接比。

## 5. dynamic_stress（套件级）

`dynamic_stress = (dynamic_pedestrian 成功 + mixed 成功) / (两场景总 runs)
= (20 + 20) / 40 = **100.0%**`（阈值 ≥90%）。

## 8. 消融对照（随行落盘 + 1 条 `--no-vo`）

正式 100 条 run 的 `ablation` 快照均为 `{vo:true, esdf:true, slack:true, terminal:true, N:40, q_ratio:0.1}`。
另行抽 1 条动态 run 做对照（独立目录，不进判读）：

| run | `ablation.vo` | 成功 | 到达 [s] | min 间隙 [m] | failure_class |
|---|---|---|---|---|---|
| `dynamic_pedestrian:16` VO on（判读数据） | true | 是 | 16.95 | 0.299 | null |
| `dynamic_pedestrian:16` VO off（`out/ablation/no_vo`） | false | 是 | 16.95 | **0.024** | null |

结论：开关生效；关闭 VO 后最小间隙从 0.299 降到 0.024（近接触），到达时间不变。该 0.024 不会进入
判读数据（对照在独立 `--out` 目录）。

## 9. 调参轮次与关键决策

| 轮次 | 参数 / 动作 | 工作集结果 | 判定 |
|---|---|---|---|
| round0（闸口1） | 默认 `d_safe=0.20`，W3 NavFn 参数 | `static_avoid_01` min 0.199 | 间距阈值必挂，进入调参 |
| round1 | `d_safe=0.30`，W3 参数，OSQP 1e-4/4000 | static 4/5；mixed_02 OSQP maximum iterations；间距中位 ~0.30；QP p95 最高 218 ms | 两个停滞 |
| round1b | 再放宽 OSQP 到 1e-3/10000 | mixed_02 无求解失败但仍超时；static_05 超时；两条路径最小间隙 0.013 / 0.088 m | **根因：全局路径穿窄缝，不是求解器** |
| round1c | `v_ref=0.45` | static_05 仍超时 | 无效，回退 0.6 |
| **round2（定稿）** | **W4 NavFn 参数（inflation 0.60 / scaling 5.0）+ d_safe=0.30 + OSQP 1e-3/10000** | **25/25 成功；间距中位 0.311~0.381；dynamic_stress 100%；QP p95 17.6~35.4 ms** | **四阈值全 PASS，冻结** |

**关键决策**：

- **W4 实例使用独立 NavFn 参数文件** `nav2_w4_params.yaml`（inflation 0.60 = robot 0.30 + d_safe 0.30，
  cost_scaling 5.0）；W3 的 S1~S3 仍用 `nav2_w3_params.yaml`（0.35 / 3.0），`run_w3.sh` 与 S2 存档基准不受影响。
- 根因：W3 的 inflation 0.35 只是代价场、不是硬约束；NavFn 会挑穿物理间隙 0.013~0.088 m 的“最短折线”。
  局部 MPC 以 `d_safe=0.30` 正确拒绝后，参考时间律很快钉在目标、路径几何丢失，表现为超时。
  全局层必须先给出与局部安全余量匹配的可行折线。
- OSQP 放宽到 `eps_abs=eps_rel=1e-3`、`max_iter=10000` **仅用于基准预设**（mixed 8 障碍时 1e-4/4000
  会 maximum iterations）；W2/W3 默认仍 1e-4/4000，S1~S3 回归逐位一致。

## 11. 局限与备注

- **动态场景为乐观上界**：合成障碍状态、无跟踪噪声；真口径以 M3 `benchmark.run()` 为准。
- **保真度**：完美运动学、20 Hz 控制、一次性规划不重规划；未加噪声/重规划。
- **急停恒 0**：Python 原型无安全急停层；指标 6 只作占位，部署期由安全层兜底。
- **间距最坏值**：dynamic_pedestrian 0.265 m、mixed 0.292 m，低于阈值 0.30；但场景级中位数
  0.304 / 0.304 达标。W4 门槛看中位数（指标定义），单 run 最坏值单列供风险参考。
- **W4 NavFn 参数**是针对“0.30 m 局部安全余量”的 W4 流水线选择；M3 正式对比使用基准套件同环境设置，
  不等同于本文的 NavFn 参数。
- 任务 #9（基线调参方案 / 入库时序 / 时限回填）仍待基线数据，不在本文伪造。

