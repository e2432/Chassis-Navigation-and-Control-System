# 障碍状态接口与跟踪归属：控制器消费障碍状态列表，跟踪独立于插件

---
status: accepted
---

自研局部控制器的动态避障输入定为「障碍状态列表」（位置 + 速度，契约话题 `/mpc/obstacles`），由独立的障碍跟踪节点（订阅点云 + odom）产出；跟踪器暂住 `mpc_controller` 包、不新增第 8 包，W5~6 实装，触发降级序④（动态砍至仅静态）则随砍。理由：controller_server 的天然输入是 costmap + odom，插件内吃原始点云别扭；状态接口让开发期合法喂合成状态，部署与打分通路只换上游跟踪器，「可迁移性」的零改动承诺不破；真值状态永不进打分通路。

**Considered Options**
- 跟踪进控制器插件（吃原始点云）：放弃——感知与控制耦合，包职责失衡；换传感器或换跟踪算法都要动控制器。
- 不建显式状态、VO 用 costmap 变化推断：放弃——栅格二值化后速度信息太糙，匀速直线短期预测失去输入。
- 状态列表接口 + 跟踪独立节点：采纳——接口在「障碍状态」处切开，Sim2Real 与迁移冒烟都在接口边界换件；范围紧张时砍跟踪器不欠接口债。
