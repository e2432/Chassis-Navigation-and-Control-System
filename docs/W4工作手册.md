### 1.3 实例加载器需求（待办 #1 实现要求）

实例表 → `mpc_proto.scenarios.Scenario` 的只读加载器。**需求而非实现**（2026-11-06 契约 v1.4 随文落下）：

**输入**：`docs/scenarios/instances.yaml`（契约 v1.4「场景实例表（schema v1）」，单表 100 实例），只读消费，不得改动表内数值；消费前确认表顶 `generator_version: 2.0.0`（重冻结，勿与旧冻结混用）。

**输出**：`Scenario` + 实例元信息（派生 `scenario_id`（`<scenario>_<run 序两位>`）/ `scenario` / `run` / `seed` / `time_limit_s`，供 runlog 指回实例表）。

**字段映射**：

| 实例表字段 | 去向 | 说明 |
|---|---|---|
| —（隐含 (0, 0, 0)） | `Scenario.start` (3,) | path frame 起点固定，表内无 `robot_start` 字段 |
| `goal` | `Scenario.goal` (3,) | path frame，直接加载不变换 |
| —（推导） | `Scenario.waypoints` | 默认取 start→goal 直线（名义行进线）；折线由调用方 `dataclasses.replace` 换 |
| `time_limit_s` | `Scenario.t_max` | 时限初值 |
| `obstacles` | `Obstacle`（velocity=0） | 圆障碍 `{x, y, r}` |
| `pedestrians` | 行人运动对象 | **常速横穿**（契约 v1.4 语义）：`x(t) = x_cross`、`y(t) = dir·speed·(t−t_meet)`，全程匀速直线、不折返、无延迟启动与停住；`dir = ±1` 为权威方向。实现沿用 grill 定案「推演层按 t 求位」——闭式函数、无积分漂移；VO 匀速预测取恒定速度 `(0, dir·speed)`（原「段速度」简化，不再分段） |
| `walls` | 墙体表达 | 实现已定（grill 定案）：**box 解析距离**为主——`distance.py` 扩有符号距离+梯度，保 narrow_passage 间距指标（指标 5）不失真；圆链近似仅作退化保底。`(x0,y0)–(x1,y1)` 为轴对齐矩形对角角点（含壁厚） |
| —（契约常量） | `goal_tolerance` | 0.25 m / 0.25 rad 硬编码对齐契约，不从表读（v1.3 实例字段作废） |
| `world_poses` / `layouts` | 不进加载器 | 算法侧只读 path frame；layouts 信息性、不作判定依据（契约 v1.4） |

**行为要求**：
- CLI 接入 `run_sim.py` / `run_w3.py`（如 `--instance <scenario>:<run>`）；S1~S3 保留为回归冒烟（`--scenario S1|S2|S3` 不动）；
- run 记录指回实例表：run.json 的 `scenario` / `seed` / `run` 取自实例元信息（`scenario` 键 / `seed` / `run`）；
- 每场景 20 实例可枚举、逐实例可复现（同表同 seed 同几何）。

**验收**：单表 5 场景各抽 1 实例做加载断言（字段映射逐项核对）+ 一次短仿真冒烟跑通；运行环境锁 conda `pro`（数值链路硬规矩，见 §4.5）。

## 2. 代码结构

### 2.1 目录与模块职责（prototype/mpc_numpy/）

| 模块 | 职责 | W4 会动到吗 |
|---|---|---|
| `run_sim.py` | W2 入口 CLI（验收表 + 诊断图 + run 记录） | 加 5 场景入口 / 加载器时 |
| `run_w3.py` | W3 入口（真 NavFn 换源编排，`dataclasses.replace` 一行换参考） | 同上 |
| `run_w2.sh` / `run_w3.sh` | 一条命令验收入口（硬编码 pro 解释器） | 否 |
| `mpc_proto/mpc.py` | **核心**：MPCConfig → SQP → condensed QP → OSQP → 回退 | 调参主要在这 |
| `mpc_proto/sim.py` | 滚动推演引擎：主循环、消融过滤、QP 计时、RunResult、验收 | 5 场景接入时 |

| `mpc_proto/reference.py` | 折线参考 + 时间律 `s(t)=min(v_ref·t, L)` + 目标截断 | 一般不动 |
| `mpc_proto/distance.py` | 解析圆盘间隙 + 梯度；`Obstacle`（匀速直线预测） | 一般不动 |
| `mpc_proto/scenarios.py` | S1/S2/S3 硬编码场景（模拟场景） | 新增基准场景加载器放这 |

| `mpc_proto/mapping.py` + `navfn_source.py` | W3：几何栅格化 / rclpy 取源壳（系统 Python） | 一般不动 |
| `mpc_proto/plotting.py` | 三联诊断图 | 否 |
| `sweep_horizon.py` / `edt_sanity.py` | N 敏感性扫描 / EDT 排雷（非验收） | 否 |

### 2.2 一次 run 的数据流

```
run_w2.sh / run_w3.sh
└─ run_sim.py / run_w3.py（argparse；消融 --no-* → MPCConfig）
   └─ sim.run(scenario, chassis, cfg)                 # 每控制拍 0.05 s：
      ① obs_now ← 场景障碍 t 时刻状态（消融 vo/esdf 在此过滤，真值裁判不过滤）
      ② MPCSolver.solve(z, obs_now, ref, t)           # SQP×n_sqp：线性化→QP→OSQP
      │   失败 → 零速回退（连续 5 拍报警）；计时即此外环
      ③ 细步积分 dt_sim=0.01（真值间隙、路径长度累计）
      ④ 到达判定（0.25 m / 0.25 rad）→ break
      └─ RunResult（zs/us/t_ctrl/clearances/qp_ms + 指标）
         ├─ runlog.write_run() → out/runs/<场景>/dev/{run.json, trajectory.npz}
         └─ plot_run() → out/<场景>.png
```

W3 差异只在参考来源：`mapping` 栅格化 → 逐场景拉起 map_server+planner_server → `navfn_source.py` 取折线 →
`dataclasses.replace(sc, waypoints=折线)`，推演与验收零改动。W4 的 5 场景变体 = 换 `scenario` 数据源（实例表加载器），**sim/mpc 不动**。

## 3. 关键参数作用与修改

### 3.1 MPC 权重与构造参数（`mpc_proto/mpc.py` `MPCConfig`，改默认值即可）

| 参数 | 默认 | 作用 | 调试方向 |
|---|---|---|---|
| `q_lat` | 4.0 | 横向误差权重 | ↑ 贴参考更紧；过大会与障碍项抢几何 |
| `q_long` | 0.4 | 沿程误差权重 | **保持 ≤ 0.1·q_lat**（定死口径）：调大会抢时间、贴障硬挤 |
| `q_theta` | 1.5 | 航向误差权重 | ↑ 车头更跟参考；死角倒车场景可观察其影响 |
| `r_v` / `r_omega` | 0.05 / 0.02 | 控制能量罚 | ↑ 输出保守（减速绕行），到达时间变长 |
| `r_dv` / `r_domega` | 0.20 / 0.10 | 控制增量罚（平滑） | ↑ 平滑度指标变好但响应钝；↓ 反之 |
| `terminal_factor` | 2.0 | 终端代价倍率（≥2× 阶段项） | ↓ 末端收敛慢；消融 `--no-terminal` 整项置 0 |
| `rho_slack` | 80.0 | 障碍软约束 L1 罚 | ↑ 离障更远、窄道更难走；S3 `max slack > 0` 属正常工作点 |
| `d_safe` | 0.20 | 软目标间隙（外缘） | 与急停阈值 0.15、间距阈值 0.3 的链条见指标定义 |
| `N` / `dt` | 40 / 0.05 | 预测时域 2 s（CLI `--N` 可改） | N 定 40 依据公式化 §10（sweep_horizon）；dt 由契约 20 Hz 定死 |
| `n_sqp` | 2 | 每拍 SQP 迭代 | ↑ 更准更慢（qp_timing.mean 涨） |
| `eps_abs/rel`、`max_iter` | 1e-4 / 4000 | OSQP 容差 | 求解失败先看回退日志，再考虑放宽 |

### 3.2 消融开关（`MPCConfig` 四布尔；CLI `--no-vo / --no-esdf / --no-slack / --no-terminal`）

| 开关 | False 语义（与 C++ 同口径） | 实证现象 |
|---|---|---|
| `vo` | 动态障碍不作匀速预测，按当前位置当静态处理 | S2 `--no-vo`：与行人接触（min 间隙 −0.030 vs 基线 +0.204）→ `failure_class=collision` |
| `esdf` | 静态障碍不进 QP 约束（真值裁判不受影响） | S1 上仅微扰——静态绕行几何由参考折线承担，属预期 |
| `slack` | 障碍约束转硬约束（QP 无 slack 变量） | 约束非激活时与软约束等价；窄道硬约束可能不可行 → 求解失败走回退 |
| `terminal` | 终端代价置 0 | 易场景上几乎无差；看长场景末端收敛 |

对照实验务必用 `--out` 分目录——模拟场景固定落 `runs/<场景>/dev/`，**重复跑会覆盖**。

| 参数 | 位置 | 值 | 说明 |
|---|---|---|---|

### 4.2 调参迭代流程（W4 调通用）

1. 改 `MPCConfig` 默认值（或 CLI `--N`）→ 只改一处，别在脚本里散改；
2. `./run_w2.sh` 回归（验收四条不容破坏，S2 数字是存档基准：13.00 s / 0.204 m / TV 0.025）；
3. 读 run.json 指标与 `qp_timing`（mean/p95 涨了说明求解变贵）；出图看行为变化落在哪段轨迹；
4. 5 场景就绪后：按调通门对基线入库数字逐场景比，只在前 5 种子上调参、全 20 上验收；
5. 每轮有效改动记进调参语境（W4 结束汇总进 `docs/基线调参日志.md` 同格式，M4 报告引用）。

### 4.3 消融对照实验

同场景跑 `--no-X` 与基线各一次，`--out` 指向不同目录，对比两侧 `run.json` 的
`metrics` / `failure_class`（`ablation` 快照会如实记录开关）。语义预期见 §3.2——
行为没变化先想「该开关在这场景是否有生效空间」（如 S1 无动态障碍，`--no-vo` 本就无差）。

### 4.4 常见故障（速查；详表见 prototype README §4）

| 现象 | 处理 |
|---|---|
| `ModuleNotFoundError: osqp` | 用错解释器——必须 pro 绝对路径（§4.1 的 PY） |
| 验收② FAIL（解算 fail > 0） | OSQP 不收敛：看回退日志；连续 5 拍报警属既定行为（零速回退、不切控制器） |
| 验收③ FAIL（间隙 ≤ 0） | 穿模/接触：先分清是算法行为还是消融开关预期（`failure_class=collision`），再查权重/场景坐标 |
| run 记录丢了 | 模拟场景落 `dev/` 会被覆盖；对照实验用 `--out` 分目录 |
| W3 get-path 重试/失败 | 换图竞态自愈 ×5；持续失败查 `out/w3_logs/*_planner.log` |
| rclpy 报错 | 取源壳必须 `/usr/bin/python3`；数值链路永在 pro |

### 4.5 环境约束（硬规矩）

- **数值链路（MPC/QP/sim/指标/出图）只在 conda `pro`**（`/home/robot/miniconda3/envs/pro/bin/python`）；
- 仅 NavFn 取源壳走 `/usr/bin/python3` + ROS Humble（零数学适配层）；
- 撞墙的解法是拆进程（subprocess），不是换数值环境。
